# Канонические инструкции для ИИ-агентов

Этот файл является главным источником инструкций для всех ИИ-агентов, работающих с репозиторием: ChatGPT/Codex, Claude, Gemini и других.

## Источник истины

GitHub repository is the source of truth.

Не полагайся на историю предыдущих чатов, если информация должна быть зафиксирована в репозитории. Сначала проверь актуальные файлы и реальный код. Не записывай предположения как факты.

## Порядок работы

Перед началом любой работы:

1. Определи проект, к которому относится запрос.
2. Прочитай этот корневой `AGENTS.md`.
3. Для работы над проектом прочитай `projects/<project-name>/AGENTS.md`.
4. Прочитай `projects/<project-name>/docs/STATUS.md` и релевантную документацию.
5. Прочитай активную задачу или specification.
6. Проверь реальный код проекта, а не делай вывод только по документации.
7. Уточни границы изменения и не изменяй другие проекты без необходимости.

Если проект не определён или неясно, где должен находиться результат, остановись и запроси уточнение.

## После выполнения работы

1. Обнови соответствующую активную задачу.
2. Если изменилось состояние проекта, обнови `docs/STATUS.md`.
3. Если изменилась архитектура, обнови `docs/ARCHITECTURE.md`.
4. Значимые архитектурные решения запиши отдельным ADR в `docs/adr/`.
5. Проверь, что документация короткая, структурированная и актуальная.
6. Не создавай дублирующую информацию в нескольких файлах.
7. Оставь в Git history историю изменений, а в документации — текущее состояние системы.

## Структура нового проекта

Каждый новый проект размещается в `projects/<project-name>/`:

```text
projects/<project-name>/
├── AGENTS.md
├── README.md
├── docs/
│   ├── OVERVIEW.md
│   ├── ARCHITECTURE.md
│   ├── STACK.md
│   ├── STATUS.md
│   ├── DATABASE.md
│   ├── API.md
│   ├── DEPLOYMENT.md
│   ├── adr/
│   └── runbooks/
├── specs/
│   ├── active/
│   └── archived/
├── tasks/
│   ├── active/
│   └── completed/
└── src/
```

Не создавай содержимое проекта, технологии, архитектуру или задачи без подтверждённых данных.

## Документация

- Считай документацию описанием текущего подтверждённого состояния.
- Отделяй факты от открытых вопросов и решений.
- Используй относительные ссылки внутри репозитория.
- Обновляй существующий канонический файл вместо создания дубликата.
- Не помещай секреты, токены, пароли или персональные данные в репозиторий.

## Изменения

- Работай только в пределах запроса.
- Для изменений предпочитай отдельную ветку и Pull Request в `main`.
- Не смешивай несвязанные изменения.
- Перед завершением проверь diff, ссылки, структуру файлов и релевантные тесты или проверки.
- Не выполняй необратимые или разрушительные действия без явного подтверждения.

## Приоритет инструкций

При конфликте применяй инструкции в следующем порядке:

1. Системные и пользовательские инструкции.
2. Этот корневой `AGENTS.md`.
3. `projects/<project-name>/AGENTS.md`.
4. Релевантные инструкции в документации проекта.
5. Инструкции текущей задачи или specification.

Более узкие инструкции не могут отменять пользовательские или системные требования.
