# TASK-0002 — Полный технический аудит с нуля по прямому запросу пользователя

## Цель

По прямому запросу пользователя: изучить репозиторий `/home/admin1/1pdf/`
и написать полную техническую документацию **с нуля**, основываясь
исключительно на исходном коде — без чтения `.md`-файлов самого проекта
(`docs/*.md`, `README.md`, `THIRD_PARTY_NOTICES.md` в `/home/admin1/1pdf/`)
и без опоры на результаты предыдущей задачи TASK-0001 как на источник
фактов (только как на список того, что уже было найдено, для сверки
полноты). Каждое утверждение — с привязкой `файл:строка`, неподтверждённое
помечено явно, а не додумывается.

## Жёсткие ограничения задачи (заданы пользователем)

- Не читать `.md`/`.mdx`/`.txt`/`.rst`/`.adoc` файлы внутри `1pdf`.
- Не использовать комментарии в коде как источник истины — при расхождении
  документировать поведение кода, отмечая расхождение.
- Не додумывать функциональность — «не реализовано», если в коде этого нет.
- Игнорировать `node_modules`, `.git`, `dist`, `build`, `coverage`.
- Явно отмечать «подтверждено кодом» vs «предположение».

   middleware, CORS-allowlist, multer-хранилище, auth-middleware,

5. Все маршруты: `admin/server.ts` целиком (~50 маршрутов),

Все ключевые факты из TASK-0001 (форк freePDF, сосуществование текущего
`/api/v1/*` и legacy ONLYOFFICE-эндпоинтов, контейнер `onlyoffice-docs` в

'\d ...'`) перепроверен и уточнён дрейф схемы с точными именами колонок.

### Новые находки, которых не было после TASK-0001

1. **`admin.html:1088,1097` вызывает `PATCH /api/auth/me/login` и
   `/password` — маршрутов нет в текущем `admin/server.ts`.** Через
   `git log -p -S "auth/me/login" -- admin/server.ts` установлено: оба
   маршрута существовали и были удалены коммитом `f1203b7` при
   рефакторинге auth-системы — это **регрессия**, а не изначально
   недостроенная функция. Открытый вопрос из TASK-0001 о происхождении
   этих вызовов закрыт.
2. **Дрейф схемы БД локализован точно**: `PaymentConfig` — базовая
   `CREATE TABLE` отсутствует во всех 5 файлах миграций (есть только
   поздний `ALTER ... ADD COLUMN alif_*`); `PaymentAttempt.external_id`
   (исходная миграция) переименован в `external_payment_id` в реальной
   БД без соответствующей миграции, плюс 5 других колонок добавлены вне
   истории.
3. **`requirePro` продублирован независимо** в `admin/server.ts:282-288`
   и `admin/routes/editorApi.ts:92-101`.
4. **`VITE_KOFI_HANDLE` не переопределяется нигде в сборке** — вероятно,
   собранный редактор до сих пор ссылается на донат-аккаунт автора
   оригинального freePDF.
5. **`DocumentVersionStatus.UPLOADING`/`FAILED` и эндпоинт
   `POST .../versions/:versionId/complete`** — реализованы на бэкенде, не
   используются ни одним найденным местом фронтенда (версии всегда
   создаются сразу `READY`).
6. **`scripts/assert-migrations-additive.sh`** — не общий guard для всех
   будущих миграций, а проверка одной конкретной, зашитой по пути в самом
   скрипте.
7. **`JWT_SECRET_OO` не имеет обязательной проверки** (дефолт — пустая
   строка), в отличие от `JWT_SECRET`.
8. Полная построчная таблица ~50 маршрутов (admin + `/api/v1/*`) с
   методом/ролью/телом/ответом и карта фронтенд→API — оба файла
   ([API.md](../../docs/API.md), [VIEWS.md](../../docs/VIEWS.md)) созданы
   заново в таком объёме.
