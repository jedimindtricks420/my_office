# AGENTS.md — MIBT

Инструкции для ИИ-агентов, работающих над документацией/задачами проекта MIBT
в `my_office`. Общие правила — в корневом [`/AGENTS.md`](../../AGENTS.md); этот
файл их не дублирует, только специфику проекта.

## Проект

- **Исходный код (source of truth для кода):** `/home/admin1/mibt-2/` —
  отдельный каталог вне `my_office`, физически принадлежит `azureuser`
  (владелец файлов на диске). Этот репозиторий (`my_office/projects/mibt/`)
  содержит только документацию и задачи, НЕ код.
- **`/home/admin1/mibt-2/` не является git-репозиторием** — `.git` отсутствует.
  Нет истории коммитов, нет возможности смотреть `git log`/`git blame` для
  датировки изменений. Единственный способ понять хронологию — mtime файлов и
  внутренние changelog-документы в `docs/`.
- **Не изменяй `/home/admin1/mibt-2/` из задач `my_office`**, если задача явно
  не требует правок кода и это не согласовано отдельно.
- В `/home/admin1/` есть устаревший каталог `MIBT/` (Vendure + React) — это
  **другой, брошенный** вариант проекта, не путать с актуальным `mibt-2/`.
  Не исследовался и не документировался в рамках этой задачи.

## Известные особенности проекта (важно для агентов)

- Приложение — один Express-процесс (порт 3000 в контейнере, проброшен на
  `127.0.0.1:13000` на хосте), обслуживающий и SSR-страницы (EJS), и JSON API
  под `/api/*`. Роль пользователя — не по поддомену (в отличие от других
  проектов на этом хосте), а по `req.session.role` (`ADMIN`/`CUSTOMER`),
  выставляемому при логине.
- Каталог `controllers/` существует в дереве проекта, но **полностью пуст**
  (только вложенные пустые подпапки `api/`, `api/admin/`) — вся логика лежит
  прямо в файлах `routes/*.routes.js` и `routes/api/**/*.js`. Не искать
  контроллеры отдельно от роутов.
- **Пул лицензий `ProductLicense` и функция `assignLicensesToOrder`
  (в `services/order.service.js`) — мёртвый код относительно текущего
  бизнес-флоу.** Согласно `docs/CHANGELOG_KEY_DELIVERY_REFACTOR.md`
  (2026-06-10, задеплоено), выдача ключей клиенту была переведена на ручной
  процесс: админ прикрепляет файлы/пишет комментарий к заказу
  (`OrderDocument`/`adminNote`), а не на автоматическое списание из пула.
  Код `assignLicensesToOrder` по-прежнему существует и импортируется в
  `routes/api/admin/index.js`, но **нигде не вызывается** — подтверждено
  прямым поиском по коду. Эндпоинт `POST /api/admin/products/:id/licenses`
  (пополнение пула) при этом всё ещё работает и доступен из UI — то есть
  можно наполнить пул, который затем никак не используется. См.
  [OPEN_QUESTIONS.md](docs/OPEN_QUESTIONS.md).
- Прямая ручная выдача лицензионного ключа на конкретную строку заказа
  (`POST /api/admin/orders/:id/lines/:lineId/licenses`, модель
  `OrderLineLicense`) — рабочий, используемый путь для передачи ключей;
  шифруется AES-256-GCM (`services/license.service.js`), расшифровывается при
  показе клиенту только когда заказ в статусе `DELIVERED`.
- Деньги — `BigInt` в тийинах (1 UZS = 100 тийин) везде в Prisma-схеме и
  сервисах баланса, кроме `QuoteRequest.totalAmount`/`vatAmount`, которые
  хранятся как `String` намеренно (комментарий в схеме: "во избежание проблем
  с BigInt сериализацией").
- Для бюджетных клиентов (`Customer.clientType = BUDGET`, B2G) баланс не
  используется вовсе — `onOrderCreated/onOrderDelivered/onOrderCancelled` в
  `services/order.service.js` явно пропускают заморозку/списание/возврат для
  этого типа (постоплата по факту, вне системы баланса).
- Курс USD получается с `cbu.uz` (ЦБ Узбекистана) с кэшем на 4 часа и
  фолбэком `13000`, если ЦБ недоступен (`services/exchangeRate.service.js`).
- Нет самостоятельной регистрации клиентов — учётки создаёт только
  администратор (`POST /api/admin/customers`, есть Joi-валидация
  `createCustomer`). Восстановление пароля — по email+OTP
  (`routes/api/auth.api.js`), это НЕ основной способ входа (вход — email +
  пароль, bcrypt).
- **CSRF-защиты не найдено** — ни `csurf`, ни аналогов в зависимостях/коде не
  обнаружено при прямом поиске. Rate limiting есть (`express-rate-limit`,
  глобально на `/api/*`, плюс отдельная зона в system nginx для
  `/api/auth/login` и `/api/auth/forgot-password`).
- Автоматических тестов нет (`jest`/`mocha`/`vitest` отсутствуют в
  зависимостях, файлов `*.test.js`/`*.spec.js` не найдено). Нет CI (папки
  `.github/workflows` нет).
- На проде (проверено `docker ps` на 2026-09-05) все 4 контейнера
  (`mibt2-app`, `mibt2-postgres`, `mibt2-nginx`, `mibt-2-db-backup-1`) подняты
  и работают **2 недели непрерывно**, ежедневные бэкапы БД идут вплоть до
  сегодняшнего дня — то есть система в проде активна и стабильна, при этом
  исходный код в `/home/admin1/mibt-2/` не менялся (по mtime) с 13 июня
  2026 — то есть с момента последнего деплоя разработка не велась.
