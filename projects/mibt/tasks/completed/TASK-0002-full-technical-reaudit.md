# TASK-0002 — Полный технический аудит с нуля по прямому запросу пользователя

## Цель

По прямому запросу пользователя: изучить репозиторий
`/home/admin1/mibt-2/` и написать полную техническую документацию
**с нуля**, основываясь исключительно на исходном коде — без чтения
верхнеуровневых `.md`-файлов самого проекта (`PRD.md`, `ARCHITECTURE.md`,
`BUSINESS_LOGIC.md`, `USER_FLOWS.md`, `BUILD_SPEC.md`, `docs/*.md` внутри
`mibt-2`) и без опоры на результаты предыдущей задачи TASK-0001 как на
источник фактов (только как на список того, что уже было найдено, для
сверки полноты). Каждое утверждение — с привязкой `файл:строка`,
неподтверждённое помечено явно, а не додумывается.

## Жёсткие ограничения задачи (заданы пользователем)

- Не читать `.md`/`.mdx`/`.txt`/`.rst`/`.adoc` файлы внутри `mibt-2`.
- Не использовать комментарии в коде как источник истины — при расхождении
  документировать поведение кода, отмечая расхождение.
- Не додумывать функциональность — «не реализовано», если в коде этого нет.
- Игнорировать `node_modules`, `.git`, `dist`, `build`.
- Явно отмечать «подтверждено кодом» vs «предположение».

## Что было найдено (кратко; полные факты — в самих документах)

Все ключевые факты из TASK-0001 (Express+EJS+Prisma+PG16 монолит, пустой
`controllers/`, `assignLicensesToOrder` мёртв, два типа клиента
`CORPORATE`/`BUDGET`, отсутствие CSRF/тестов/CI/git) **воспроизведены
независимо и подтверждены повторно**, код не менялся.

### Новые находки, которых не было после TASK-0001

1. **Миграции Prisma не покрывают таблицы КП** (`QuoteRequest`/
   `QuoteDocument`/`QuoteDownloadToken`) — ни одна из 3 миграций их не
   создаёт, и нигде не вызывается `prisma migrate deploy`
   (`prisma/schema.prisma:322-370` vs `prisma/migrations/*/migration.sql`).
2. **`logAudit()` (`services/audit.service.js:3`) нигде не вызывается** —
   страница `/admin/audit` гарантированно всегда пуста в текущем коде.
3. **`middleware/upload.js` — мёртвый файл**, не импортируется нигде;
   реальные загрузчики документов определены заново локально в
   `documents.api.js`/`quotes.api.js`.
4. **`schemas.createCustomer` (`middleware/validate.js:41`) определена, но
   не подключена** к `POST /api/admin/customers` — нет серверной
   валидации ИНН/МФО/счёта при создании клиента.
5. **Два обработчика без проверки `!order`** в `routes/api/admin/index.js`
   (`/orders/:id/cancel` строка 531, `/orders/:id/status` строка 556) —
   упадут с 500 вместо 404 на несуществующем заказе.
6. **Поля `DocumentDownloadToken.used` и `.token`** определены в схеме, но
   не используются кодом (поиск/удаление — по `id`, не по `token`; `used`
   не читается, вместо него запись удаляется целиком).
7. **`public/test-products.html`** — забытый статичный макет, публично
   доступен без авторизации через `express.static('public')`.
8. **Расхождение комментария и кода**: `routes/api/quotes.api.js:147`
   утверждает «без авторизации», но роут смонтирован под `requireAuth`.
9. **Несогласованная валидация пароля**: клиент — `minlength="8"`
   (`views/auth/reset-password.ejs`), сервер — Joi `min(10)` + буква+цифра.
10. **Нет UI ни для одного из двух эндпоинтов пула лицензий**
    (`POST /api/admin/products/:id/licenses`,
    `POST /api/admin/orders/:id/lines/:lineId/licenses`) — подтверждено
    построчным просмотром всех `.ejs`, не только `grep`.
11. Точное число `.ejs`-шаблонов уточнено — **35** (в предыдущей сводке
    STATUS.md TASK-0001 фигурировала опечатка «35» в одном месте и «30» в
    другом черновике этой задачи — исправлено на подтверждённые 35 везде).
