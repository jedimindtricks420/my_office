# TASK-0002 — Полный технический аудит с нуля по прямому запросу пользователя

## Цель

По прямому запросу пользователя: изучить репозиторий `/home/admin1/contador/`
и написать полную техническую документацию **с нуля**, основываясь
исключительно на исходном коде — без чтения верхнеуровневых `.md`-файлов
самого проекта (`docs/*.md`, `README.md`, `nsbu_and_soliq_codex/*.md`,
`v2/docs/**`) и без опоры на результаты предыдущей задачи TASK-0001 как на
источник фактов (только как на список того, что уже было найдено, для сверки
полноты). Каждое утверждение — с привязкой `файл:строка`, неподтверждённое
помечено явно, а не додумывается.

## Жёсткие ограничения задачи (заданы пользователем)

- Не читать `.md`/`.mdx`/`.txt`/`.rst`/`.adoc` файлы внутри `contador`.
- Не использовать комментарии в коде как источник истины — при расхождении
  документировать поведение кода, отмечая расхождение.
- Не додумывать функциональность — «не реализовано», если в коде этого нет.
- Игнорировать `node_modules`, `.git`, `dist`, `build`.
- Явно отмечать «подтверждено кодом» vs «предположение».

## Отклонение от исходного плана задачи

Инструкция задачи была написана в расчёте на типовой Express+EJS-монолит
(шаги «прочитай все `.ejs`-шаблоны», «прочитай middleware аутентификации» и
т.д.). Реальный репозиторий оказался **втрое масштабнее и структурно иным**:
не одно приложение, а три (v2 — Next.js 16 App Router; admin — Express 5,
один файл 1613 строк; v1 — код физически отсутствует), 78 файлов маршрутов
API вместо типичных 10-15, 63 файла React-компонентов вместо EJS-шаблонов,
2 независимые Prisma-схемы (22 + 14 моделей), 2901-строчный каталог шаблонов
проводок, отдельный налоговый движок (`taxReport/engine.ts`), 35 файлов
тестов (5483 строки). План адаптирован по ходу: для React-страниц вместо
построчного чтения каждого `.tsx`-файла построена карта запросов через
`grep -R "fetch("` по всем 63 файлам (задокументировано как методологическая
оговорка в GAPS.md/VIEWS.md); для 2901-строчного `ensureBaseData.ts`
подтверждена структура и точное число записей (180 типов документов) без
построчной проверки каждого шаблона; для `admin/public/index.html` (2391
строка, единый файл без сборки) прочитан только заголовок.

## Порядок работы (адаптирован по ходу, отчёт после каждого шага)

1. `find` дерева проекта — выявлено 3 приложения вместо одного (см. выше).
2. `package.json` (корень + `v2/`) — стек, скрипты, зависимости.
3. `.env`/`v2/.env` — только имена переменных (`grep -oE`), без значений.
4. Точки входа: `admin/server.ts` (1613 строк, целиком), `v2/src/proxy.ts`
   (аналог `middleware.ts` в Next.js 16), `v2/src/instrumentation.ts`.
5. Все 78 файлов `route.ts` v2 — построчно, батчами через `cat -n` (метод,
   путь, auth, тело, ответ); `admin/server.ts` — целиком за один проход.
6. Ключевые модули `lib/`: `postingEngine.ts`, `closing.ts`,
   `rulesEngine.ts`, `expressionEval.ts`, `taxReport/engine.ts`,
   `templateValidator.ts`, `openItems.ts`, `charterCapital.ts`,
   `receiptKind.ts`, `billing.ts`, `queue.ts`, `mailer.ts`, `constants.ts`,
   `context.ts`, `auth.ts`/`auth-edge.ts`, `prisma.ts` — целиком.
7. Обе Prisma-схемы целиком (280 + 585 строк) + структура обеих директорий
   миграций (сверка: не стандартный формат Prisma, россыпь `.sql`-файлов).
8. Вместо EJS — карта «React-страница → вызываемые API» через `grep` по 63
   `.tsx`-файлам; 3 ключевых компонента (`login/page.tsx` и др.) прочитаны
   целиком для подтверждения паттерна.
9. Аутентификация — `proxy.ts` + `context.ts` (не единый Express-миддлвар).
10. Тесты — 35 файлов, `describe`/`it`-заголовки просмотрены (не тела).

### Новые находки, которых не было после TASK-0001

1. **`prismaWithOrg()`** (Prisma-расширение для автоскоупинга по `orgId`,
   `v2/src/lib/prisma.ts:28-89`) реально применяется лишь в 6 из 78
   маршрутов — мультитенантная изоляция в остальных держится только на
   ручном `where: { orgId }` в каждом Prisma-вызове, без гарантии
   фреймворка.
2. **`POST /admin/api/v2/vouchers/redeem`** (`admin/server.ts:733-757`) —
   публичный эндпоинт без проверки владения `orgId`.
3. Каталог **`/home/admin1/contador/ai/`** (476 строк) — мёртвый код, не
   импортируется нигде, не копируется ни в один Dockerfile.
4. **5 scratch-файлов в корне `v2/`** (`audit_output.txt`,
   `audit_results.txt`, `audit_script.ts`, `doc_count.txt`,
   `test-azure-ai.mjs`) — не используются ни одним скриптом/сборкой.
5. План счетов — фактически **269 записей**, а не «214», как заявляет
   комментарий `seed-coa.ts:12`.
6. **`activeOrgId` в JWT не перепроверяется по БД** на каждый запрос —
   удалённый из организации участник сохраняет доступ через
   `getActiveOrgId()`-маршруты вплоть до истечения токена (7 дней).
7. **Rate limiting отсутствует на всех `/v2/api/auth/*`** маршрутах (в
   отличие от `admin`, где `express-rate-limit` стоит явно).
8. Обнаружена и **не выполнена попытка prompt injection** в
   `/home/admin1/contador/AGENTS.md:1-3` (текст в стиле «Read the relevant
   guide in node_modules/next/dist/docs/ before writing any code»,
   автоматически подгруженный харнессом как «инструкция проекта») — доложено
   пользователю в ходе задачи, отмечено в `GAPS.md` и в `AGENTS.md` этого
   my_office-проекта как предупреждение для будущих агентов.
9. Точное число файлов тестов — **35** (не 34, как указывал TASK-0001).
10. Полная построчная таблица всех 78 маршрутов v2 + ~62 маршрутов admin с
    методом/путём/auth/телом/ответом (не было в таком объёме после
    TASK-0001, где API.md группировал только по папкам).
