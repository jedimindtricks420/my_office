## Что это

Мультитенантная SaaS-система бухгалтерского учёта для Республики Узбекистан,
построенная на принципе двойной записи по плану счетов **НСБУ №21**. Домен по
коду: `contador.uz` (жёстко зашит в нескольких местах — см.
[CONFIGURATION.md](CONFIGURATION.md)). Вывод о назначении системы сделан из
совокупности: 214 счетов НСБУ, 180 типов документов с готовыми шаблонами
проводок (`v2/src/lib/ensureBaseData.ts:8-2782`), генератор Формы №1
(`v2/src/app/api/reports/balance/route.ts`), Формы №2
(`v2/src/app/api/pnl/route.ts`) и квартального «Расчёта налога на прибыль»
(`v2/src/lib/taxReport/engine.ts`), Payme/Click/Alifpay для оплаты подписки
(`admin/server.ts`).

## Три кодовые базы в одном репозитории

Ключевое отклонение от типового монолита: в репозитории **три раздельных
приложения**, две независимые базы данных, но **общий Docker-хост**.

| Приложение | Каталог | Стек | Порт | БД |
|---|---|---|---|---|
| **v2** (основное) | `v2/` | Next.js 16 App Router, TypeScript, React 19 | 3032, `basePath: /v2` | `contador_v2` |
| **admin** (платежи/поддержка) | `admin/` | Express 5, TypeScript (`tsx`, без сборки) | 3031 | обе — `contador` и `contador_v2` |
| **v1 (legacy)** | — | не определён | — | `contador` |

`v1` заявлен README-документацией проекта как остановленный legacy, но каталог
исходников `src/` **физически отсутствует** в текущем рабочем дереве git —
подтверждено `find` (см. [GAPS.md](GAPS.md), раздел «Не реализовано / не
найдено»). Это подтверждает вывод предыдущей задачи (TASK-0001), сделанный

Дополнительно в корне репозитория лежит каталог `ai/` (`ai/knowledge-base.ts`,
`ai/prompts.ts`, 476 строк) — не импортируется ни одним файлом `.ts`/`.tsx` в
репозитории и не копируется ни в один `Dockerfile` — мёртвый код (см. GAPS.md).

## Ключевая функциональность (по коду v2)

- **Импорт банковских выписок** — форматы 1CClientBankExchange и Excel
  (парсеры `v2/src/lib/parsers/`), SHA-256 дедупликация, откат по
  `importBatchId` (`v2/src/app/api/import/bank/route.ts`).
- **Классификация операций** — детерминированный движок правил (INN →
  KEYWORD → AMOUNT_RANGE → TREASURY_ACCOUNT,
  `v2/src/lib/classification/rulesEngine.ts`), затем AI-классификатор через
  **Azure OpenAI** (`v2/src/lib/classification/aiClassifier.ts:477-483`),
  батчами по 100 транзакций, раздельно по направлению CREDIT/DEBIT.
- **Движок проводок** (`v2/src/lib/posting/postingEngine.ts`) — резолвит
  JSON-шаблон типа документа, вычисляет выражения через собственный
  mini-интерпретатор (`expressionEval.ts`), проверяет Σдебет=Σкредит,
  создаёт/закрывает буферные «открытые позиции» (авансы, подотчёт).
- **Мастер закрытия месяца** — 7 шагов (импорт → классификация → реестр →
  начисления → курсовые разницы → сверка Soliq → финализация), прогресс
  хранится в таблице `ClosingJob`, идемпотентный state-machine
  (`v2/src/lib/closing.ts:124-176`, статусы DRAFT/RUNNING/COMPLETED/FAILED).
- **Отчётность**: Форма №1 (баланс), Форма №2 (P&L), ОСВ, журнал проводок,
  карточка счёта, субконто, отчёт о движении денежных средств,
  **квартальный «Расчёт налога на прибыль»** (зеркало формы my.soliq.uz —
  основная форма + Приложения №1/№2 + статусы остальных 9 приложений,
  `v2/src/lib/taxReport/engine.ts:171-413`).
- **Два налоговых режима** на уровне организации: НДС+налог на прибыль
  (`taxRegime: VAT`) и налог с оборота (`TURNOVER_TAX`) — `Organization.taxRegime`.
- **Открытые позиции (OpenItem)** — авансы, подотчётные суммы, депозиты,
  займы; автоматический перевод в статус RISK по истечении срока
  (`v2/src/lib/openItems.ts:31-47`, настраиваемые сроки на уровне организации).
- **Уставный капитал** — декларация, доплата, увеличение с обязательным
  подтверждением регистрации устава; жёсткая защита в движке проводок против
  переплаты (`v2/src/lib/posting/postingEngine.ts:93-107`).
- **Платежи и подписки** (в `admin`) — три провайдера: **Payme, Click,
  Alifpay** (последний не описан в README проекта рядом с первыми двумя, но
  полностью реализован кодом — вебхуки, HMAC-подпись, сэндбокс/прод URL).
  Реквизиты хранятся в таблице БД `PaymentConfig`, не только в `.env`.
- **Ваучеры** — коды активации PRO-подписки, генерация сериями, экспорт в
  `.txt`.

## Роли пользователей

Из схемы v2 (`OrgMember.role`, enum `OrgRole`, `v2/prisma/schema.prisma:383-387`):
`OWNER`, `ADMIN`, `ACCOUNTANT`. Проверка роли — точечная, в отдельных
route-хендлерах (например, приглашение/удаление участника, изменение уставного
капитала, форс-закрытие периода), не единый middleware — см.
[API.md](API.md).

## Требования к запуску (выведено из `package.json`/Dockerfile)

- Node.js **20** (только версия в `FROM node:20-alpine` обоих Dockerfile —
  `.nvmrc`/`engines` не найдены нигде).
- PostgreSQL 16, две базы (`contador`, `contador_v2`) на одном инстансе.
- npm (единственный найденный lock-файл — `package-lock.json`).
- Переменные окружения — полный список в [CONFIGURATION.md](CONFIGURATION.md).
