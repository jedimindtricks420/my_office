## Инфраструктура / деплой

1. **Что такое два запущенных v1-контейнера (`contador-app`,
   `f7ee8a3d81b8_contador-app`) и обслуживают ли они реальный трафик?**
   Каталог `src/` физически отсутствует в текущем рабочем дереве репозитория,
   README называет v1 остановленным, но `docker ps` показывает оба контейнера
   в статусе `Up` (2 недели), один с проброшенным портом 3030. Неясно: это
   забытые/осиротевшие контейнеры, которые можно безопасно остановить, или
   активно используемый сервис, который README и текущий `git` не отражают?
   Требует уточнения у владельца системы, не восстанавливается из кода.
2. **Почему `contador-app` не публикует порт наружу**, а
   `f7ee8a3d81b8_contador-app` — публикует 3030? Два похожих контейнера
   одновременно — намеренное A/B-состояние, забытый дубликат после

3. Реальные значения переменных окружения (`.env`) не читались согласно
   требованию задачи — соответственно, работоспособность/актуальность
   конкретных ключей (JWT-секрет, ключи Azure OpenAI, реквизиты Payme/Click/
   Alifpay) не проверялась.
4. Расписание/автоматизация резервного копирования БД не найдено (в

## Код / архитектура

7. **Не проверено по всем 78 маршрутам v2**, что каждый из них корректно
   фильтрует данные по `orgId` (мультитенантность). Проверена лишь выборка
   (`pnl`, `classification/run-rules`, `classification/run-ai`,
   `classification/status/[periodId]`). Требуется отдельный код-ревью, если
   нужна полная гарантия tenant-изоляции.
8. Не найден файл `middleware.ts` в исходниках `v2/src` — предполагается, что
   авторизация полностью реализована на уровне отдельных route-хендлеров
   через `context.ts`, но это не единый enforced-слой на уровне фреймворка;
   не проверялось, есть ли маршруты, забывшие вызвать `getActiveOrgId()`/
   `getActiveMembership()`.
9. Реальное использование переменных `PAYME_MERCHANT_ID`/`CLICK_SERVICE_ID`/
   `CLICK_SECRET_KEY` из корневого `.env` неясно — код `admin/server.ts`, по
   имеющимся данным, читает реквизиты платёжных провайдеров из таблицы БД
   `PaymentConfig`, а не напрямую из `process.env`; не проверено построчно,
   есть ли места, где `.env`-значения всё же используются как фолбэк.
10. Тестовые скрипты `test-payme.sh`/`test-payments.sh` в корне репозитория
    содержат захардкоженные тестовые ключи/ID прямо в версионируемом файле —
    не проверялось, тестовые ли это ключи песочницы провайдера (безопасно) или
    что-то, требующее ротации; сами значения не читались и не копировались в
    эту документацию.
