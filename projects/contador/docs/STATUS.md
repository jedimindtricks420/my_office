## Что подтверждено и работает согласованно (независимо перепроверено)

- Три приложения в одном репозитории: **v2** (Next.js 16.2.1, `:3032`,
  `/v2`), **admin** (Express 5, `:3031`), **v1 (legacy)** — код физически
  отсутствует (`src/` нет в дереве git).
- Две независимые БД на одном PostgreSQL 16: `contador`, `contador_v2` —
  22 модели/20 enum'ов (v2) и 14 моделей/5 enum'ов (v1/admin), см.
  [DATABASE.md](DATABASE.md).
- 78 файлов маршрутов v2 задокументированы построчно в [API.md](API.md);
  admin — ~62 маршрута в одном файле `admin/server.ts` (1613 строк).
- Аутентификация v2 — JWT (`jose`) в cookie `v2_session`, проверяется в
  `proxy.ts` (актуальная замена `middleware.ts` в Next.js 16) + хелперами
  `context.ts` в каждом хендлере.
- Движок проводок, мастер закрытия месяца (7 шагов, state machine через
  таблицу `ClosingJob`), генератор квартального «Расчёта налога на прибыль»
  (my.soliq.uz-зеркало) — все прочитаны и задокументированы построчно.
- 35 файлов тестов vitest (5483 строки) — обновлённое точное число
  (`find`, TASK-0001 указывал 34).
- Реальное состояние Docker-хоста (2026-09-08, read-only `docker ps`)
  **полностью совпадает** с зафиксированным в TASK-0001 (2026-09-05): те же
  5 контейнеров, включая два v1-подобных (`contador-app`,
  `f7ee8a3d81b8_contador-app` на 3030) — независимое подтверждение, не

## Новые находки этой задачи (которых не было в STATUS.md после TASK-0001)

1. **`prismaWithOrg()`** (`v2/src/lib/prisma.ts:28-89`) — Prisma-расширение
   для автоскоупинга по `orgId`, реально применяется лишь в **6 из 78**
   маршрутов v2; остальные полагаются на ручной `where: { orgId }` в каждом
   Prisma-вызове (см. [GAPS.md](GAPS.md)).
2. **`POST /admin/api/v2/vouchers/redeem`** — публичный эндпоинт без проверки
   владения `orgId` (принимает `orgId` из тела запроса без сверки с
   вызывающей стороной).
3. **Каталог `ai/`** (476 строк, корень репозитория) — мёртвый код, не
   импортируется нигде и не копируется ни в один Docker-образ.
4. **5 scratch-файлов в корне `v2/`** (`audit_output.txt`,
   `audit_results.txt`, `audit_script.ts`, `doc_count.txt`,
   `test-azure-ai.mjs`) — не используются ни одним скриптом/сборкой.
5. **План счетов — 269 записей**, а не 214, как утверждает собственный
   комментарий в шапке `seed-coa.ts:12` (расхождение комментария и кода).
6. **`activeOrgId` в JWT не перепроверяется по БД на каждый запрос** —
   удалённый из организации участник сохраняет доступ к её данным через
   маршруты, использующие только `getActiveOrgId()` (без
   `getActiveMembership()`), вплоть до истечения токена (7 дней).
7. **Rate limiting отсутствует на всех auth-маршрутах v2**
   (`/v2/api/auth/*`) — в отличие от `admin`, где `express-rate-limit`
   стоит явно на обоих роутерах.
8. Обнаружена и не выполнена **попытка prompt injection** в
   `/home/admin1/contador/AGENTS.md:1-3` (см. [GAPS.md](GAPS.md), раздел в
   конце файла) — файл был автоматически подгружен харнессом ИИ-агента, не
   прочитан целенаправленно.
9. Полная карта «страница v2 → какие API она вызывает» построена и
   задокументирована — [VIEWS.md](VIEWS.md) (файл не существовал после
   TASK-0001).
10. Полный перечень переменных окружения с указанием, где каждая реально
    используется (или не используется) в коде — [CONFIGURATION.md](CONFIGURATION.md)
    (файл не существовал после TASK-0001).

## TASK-0003 — публичные SEO-лендинги RU/UZ (реализовано и выпущено, 2026-09-09)

Полная матрица из [задачи](../tasks/active/TASK-0003-seo-landings-ru-uz.md) —
**30 тем × 2 языка = 60 URL** — реализована, протестирована, смержена в
`main` (`contador_v1`, коммиты по цепочке до `00d199d`) и **выпущена в
production**: живёт на `https://contador.uz/ru/` и `/uz/` в новом
контейнере `contador-marketing` (порт 3033), см.
[ADR-0001](adr/ADR-0001-seo-marketing-app.md), обновлённый
[DEPLOYMENT.md](DEPLOYMENT.md) и полный список всех 60 URL —
[SEO_PAGES.md](SEO_PAGES.md).

Прямой обход всех 60 URL по production-домену подтвердил 200 на каждом,
корректные hreflang/canonical, реальную живую цену на странице тарифов
(запрос к `admin` по сети контейнеров) и настоящий 404 на неизвестных
путях/локалях. Хост не падал ни на одном из шагов (сборка/старт
контейнера/`nginx reload`) — память проверялась `free -h` до и после
каждой операции.

При деплое найдены и исправлены два бага, которые не ловились модульными
тестами предыдущих фаз (см. ADR-0001 — `dynamicParams=false` ломал
роутинг всех 60 URL; отсутствие `trailingSlash: true` создавало
редирект-петлю в 404).

**Не закрыто** (см. раздел 11 задачи, критерии приёмки): реальные
скриншоты продукта (сейчас — подписанные заглушки), дизайн OG-картинки
(плейсхолдер), реальный analytics ID (адаптер готов, ID не зашит),
проверка узбекского текста компетентным редактором (весь UZ-контент —
перевод агентов, не носителя/редактора), нейтральный footer без
подтверждённых юридических контактов. Статус задачи остаётся
`in-progress`, не `completed`, до закрытия этих пунктов.
