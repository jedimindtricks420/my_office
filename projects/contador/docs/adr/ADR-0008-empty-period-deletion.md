# ADR-0008: Удалять только пустые учётные периоды

- Дата: 2026-09-10
- Статус: локально реализовано, без выпуска
- Задача: TASK-0005, частичная защита ACC-003/ACC-023

## Контекст

DELETE периода последовательно удалял долги, проводки, документы, импорт и
календарь без транзакции и ограничения роли. Долг прошлого месяца также
исчезал, если документ его погашения относился к удаляемому месяцу.
SoliqImportBatch/ClosingJob имеют каскадные связи с Period.

## Решение

API требует актуальную роль OWNER/ADMIN. Удалять разрешено только OPEN период
без lockDate, closingData и записей во всех пяти Period-отношениях:
documents, stagedTransactions, taxEvents, closingJobs, soliqImportBatches.
Существующие ссылки своей организации correctionForPeriodId и affectedPeriodId
также блокируют удаление. Любой статус записи учитывается; пустое DRAFT-задание
мастера не считается разрешением уничтожить историю. Заполненный период
возвращает 409 PERIOD_NOT_EMPTY; отдельной очистки зависимостей нет.

Транзакция сначала получает tenant-ограниченный FOR UPDATE на Period, затем
проверяет состояние/связи, удаляет пустой период и создаёт DELETE_PERIOD с
актуальным пользователем и прежними year/month/mode/status. MaxWait 5 с,
timeout 10 с. Ошибка аудита откатывает удаление. FOR UPDATE здесь нужен для
конфликта с FK KEY SHARE новых дочерних записей; FOR NO KEY UPDATE обычного
проведения не обеспечивает такую защиту удаления.

## Проверка

19 API-тестов и 14 PostgreSQL-тестов прошли после ограничения роли.
SQL проверяет откат ошибки аудита и повтор, параллельные DELETE (200/404,
один аудит), отказ конкурентной вставки Document по lock_timeout 500 мс,
сохранность долга предыдущего месяца и его проводок, VOIDED-документа,
банковского импорта, календаря, ClosingJob, READY/POSTED/CANCELLED Soliq,
а также существующих строковых ссылок из другого месяца. Проверки выполнялись
только на bounded disposable-БД, без production HTTP и браузера.

## Ограничения

- Это не реализация архивирования и неизменяемых версий документов.
- Любой ранее созданный ClosingJob запрещает физическое удаление периода,
  даже если он появился при чтении мастера и суммы нулевые.
- FOR UPDATE защищает FK-вставки, но не произвольные конкурентные записи
  correctionForPeriodId/affectedPeriodId без FK и согласованного lock-протокола.
- Прямой SQL DELETE и каскад удаления Organization этим API не защищены;
  у Soliq по-прежнему нет SQL-триггера запрета DELETE. Это релизное ограничение.
- Тест гонки нового документа не является полным нагрузочным тестированием
  всех источников записи и последовательностей блокировок.
- Rollback банковского импорта и пересчёт остатка этим изменением не исправлены.
- Production-схема, данные, сборки и сервисы не изменялись. ACC-023 целиком
  и G0-G4 не приняты.
