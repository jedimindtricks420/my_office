# ADR-0002 — Транзакционная защита проведения до внедрения регистров

Дата: 2026-09-10. Статус: реализовано локально, не выпущено.
Контекст: [TASK-0005](../../tasks/active/TASK-0005-accounting-correctness-remediation.md).

## Решение

Сервис post/void/repost открывает ограниченную транзакцию (ожидание 5 с,
выполнение 30 с) при корневом PrismaClient или использует переданную.
Ошибки календаря пробрасываются; журнал, позиции и AuditLog откатываются вместе.
Внешняя транзакция сохраняет собственные лимиты и обязана пробросить ошибку.

Document блокируется FOR UPDATE до проверки наличия проводок. Period
блокируется FOR NO KEY UPDATE до проверки организации/даты/открытости.
Первый вариант FOR UPDATE на Period воспроизвёл deadlock двух транзакций,
создавших документы с FK на один период: обе держали KEY SHARE.
FOR NO KEY UPDATE совместим с FK KEY SHARE; исправление проверено на PostgreSQL 16.
Проведения одного периода сериализуются, что ограничивает пропускную способность.
Гонки закрытия и операций нескольких периодов требуют отдельного решения.

Подготовленные денежные строки сравниваются в целочисленных сотых (BigInt),
без потери копеек при сумме, превышающей precision Decimal. Промежуточные
вычисления формул и отчётные агрегаты этим решением не исправлены.

До появления регистра распределений OpenItem закрывается только при точном
совпадении суммы; позиции блокируются в порядке dateOpened/id. При наличии
долга без совпадения частичная оплата/переплата отклоняется. Массовый DONE
налоговых событий по одному платежу удалён. Это ограничения, а не завершение
учёта частичных оплат и налоговых расчётов.

## Последствия и границы

- Нельзя использовать успешный post как доказательство полноты первички или налоговой корректности.
- Отдельно созданный POSTED может остаться без проводок; создание должно войти во внешнюю транзакцию.
- Удаление проводок при void сохранено; неизменяемое сторно, версии и уникальность активного набора в БД не реализованы.
- Дробные результаты с более чем двумя знаками отклоняются до утверждения округления.
- Проверка членства усилена, но все API и межорганизационные ссылки ещё не проверены.
- READ ONLY аудит даёт 14 агрегированных диагностик, не заключение о корректности учёта; эвристические дубли требуют разбора.

Проверено 282 тестами, включая 8 на одноразовой БД, TypeScript и scoped ESLint.
Рабочие данные и Docker-сервисы не обновлялись. G0 и последующие ворота остаются открытыми.
