# ADR-0004: Защита до реализации регистров расчётов и договоров

Дата: 2026-09-10. Статус: реализовано локально, не выпущено. TASK-0005.

## Причина

Прямое изменение статуса OpenItem позволяло убрать долг без документа расчёта.
JournalEntry.contractId не имеет связанного реестра или внешнего ключа;
произвольную строку нельзя проверить на принадлежность организации.
Явный counterpartyId игнорировался при поиске контрагента по ИНН/имени.

## Решение

- Close/reopen OpenItem после проверки доступа возвращают 409 без записи.
  Соответствующие ручные действия удалены из UI; старые закрытия без документа
  помечены как требующие сверки, но автоматически не исправляются.
- Непустой contractId или договорная аналитика шаблона блокируют проведение.
  Это временное ограничение, не реализация реестра договоров.
- Явный контрагент проверяется по id + orgId, переданный ИНН должен совпадать.
  Ошибочный выбор не заменяется новым контрагентом; без id сохраняется поиск
  по ИНН/имени. Структурированные значения вместо строк отвергаются.
- Сумма создания долга и фактически выполняемого погашения проверяется до записей:
  конечная, положительная, представимая в Decimal(20,2) без округления.
- Void/repost источника погашенного долга запрещён под блокировкой OpenItem.
  Сначала отменяется расчёт. При отмене непогашенного источника учитывается RISK.
  Явный openItemId ограничивает погашение выбранной позицией без подмены.
- Предпросмотр Soliq не сопоставляет разные непустые ИНН. Проведение повторно
  проверяет выбранный аванс под row lock: организация, статус, источник,
  ИНН, счёт, дата и точная сумма. Зачёт банковской строки без регистра
  использования платежей и допуски по сумме отклоняются, а не имитируются.
- Завершение шага требует бухгалтерской роли; Period lock предшествует
  advisory lock импорта. Маркер, проводки, зачёты и ClosingJob атомарны.
  saveClosingState принимает существующую транзакцию; аудит проводок хранит актёра.

## Последствия

Частичные оплаты, распределения, остатки, валюта и исправление исторических
ручных закрытий требуют полноценной модели и сверки. Пока сохраняется только
точное автоматическое погашение по существующим правилам. Большинство базовых
шаблонов ещё не содержит контрагентской аналитики. Полная бухгалтерская готовность
и выполнение ACC-002/003/056 этими ограничениями не заявляются.
Изначальное ограничение о недоверенном клиентском parsedPayload/taxSummary
заменено серверным batch в [ADR-0005](ADR-0005-soliq-server-batch.md).
Неизменяемая отмена и восстановление исходного RISK не реализованы;
ACC-005/006 и полный жизненный цикл расчётов остаются открытыми.
