# ADR-0005: Серверный пакет Soliq

- Дата: 2026-09-10.
- Статус: реализовано локально, не выпущено; TASK-0005 остаётся active.
- Контекст: ACC-005 позволял заменить финансовые данные между разбором Excel
  и проведением; отказ отдельной операции мог оставить частичный результат.

## Решение

SoliqImportBatch принадлежит организации и периоду. Сохраняются исходные байты,
SHA-256, версия парсера, строки со стабильными rowId, fixed-2 суммы, итоги и автор.
Уникален orgId/periodId/sourceHash. Составной FK не допускает чужой период.
Клиент передаёт только batchId и решения rowId/openItemId/receiptKind, не суммы.

Транзакция блокирует Period FOR NO KEY UPDATE, batch FOR UPDATE, затем выбранные
OpenItem; повторно проверяет период, источник и контрольные итоги. Документы,
точные зачёты, аудит, прогресс мастера и POSTED фиксируются вместе. Независимая
проверка soliqLedger сравнивает фактические стороны/счета/суммы восьми типов
документов, а не только равенство дебета и кредита. Протокол содержит связи
строк с документами, решения, итоги и ledgerControl версии soliq-v1.

READY доступен для восстановления и блокирует закрытие. Отмена только с причиной
в открытом периоде переводит его в CANCELLED, сохраняя источник и автора/время.
POSTED/CANCELLED неизменяемы для UPDATE. Skip запрещён при READY/POSTED или
старом маркере. Повторный вход после проведения только переключает шаг мастера.
Архив и предпросмотр предоставляют оригинал/JSON-протокол через отдельный GET
export; проверяются текущее членство, организация batch/периода и SHA-256.
Выгрузка доступна и в закрытом периоде, не меняет БД; ответы attachment/no-store
и nosniff. При смене периода Step6 пересоздаётся, поздний onNext игнорируется.

## Миграция

В кодовом репозитории: v2/prisma/migrations/20260910_soliq_import_batch.sql.
Реальный процесс проекта: raw SQL через psql, не prisma migrate deploy/db push.
Миграция транзакционная, содержит таблицу, индексы/FK, CHECK и UPDATE-триггер.
Применение и повторный запуск проверены только на ограниченной одноразовой
PostgreSQL 16 после схемы из HEAD. Production-миграция не выполнялась.
До выпуска нужны проверка дрейфа схемы, отчёт dry-run и план восстановления.
Дополнительный SQL-тест дважды применяет тот же файл через установленный Prisma
db execute с явным disposable URL: READY/POSTED/CANCELLED полностью сохранены,
терминальные записи по-прежнему защищены. Это не prisma migrate deploy.

## Проверки и ограничения

На 18:13:56 прошли 627 тестов/33 файла, включая 66 PostgreSQL-проверок;
24 SQL-теста Soliq проверяют зачёты/НДС, откаты, гонки, изоляцию, повреждённый
источник, неизменяемость и обязательность протокола отмены. TypeScript и scoped
ESLint прошли. Изолированный браузерный стенд проверяет реальный Step6 с
синтетическим API, не аутентифицированный Next.js E2E.

Дополнительно прошли 12 тестов экспорта и 27 PostgreSQL-тестов Soliq вместе с
повторным применением миграции. Браузер подтвердил архив/ссылки и отсутствие
перехода от запоздалого ответа старого периода. Событие сохранения скачанного
файла во встроенном браузере не получено; точные HTTP-байты проверены тестами.

Не реализованы защита DELETE/каскада, полный контроль
ресурсов XLSX, валютные распределения, общее исключение двойного признания и
юридическая проверка вычета НДС. Идентификаторы/номера исходных ЭСФ не образуют
независимый реестр. Сохранение документа/проводки не стало неизменяемым сторно.
Проверки не заменяют бухгалтерскую приёмку и ворота G0-G4.
