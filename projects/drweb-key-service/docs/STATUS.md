## Что подтверждено и работает

- Два Docker-контейнера из одного образа: **`drweb-api`** (FastAPI/uvicorn,
  порт 8001) и **`drweb-admin`** (Django 5.x runserver, порт 8002) — оба
  `Up 2 недели` на момент проверки, порты проброшены на `0.0.0.0`.
- Единственный бизнес-эндпоинт `POST /drweb/api/v1/generate` резолвит `sku`
  через локальную таблицу `product_mapping` (7 записей на момент проверки,
  из `app/products.json`), запрашивает ключ у Dr.Web через `curl_cffi`
  (эмуляция TLS-отпечатка Chrome для обхода QRATOR) и логирует результат в
  `key_logs`. Подробности — [API.md](API.md), [ARCHITECTURE.md](ARCHITECTURE.md).
- Django Admin на порту 8002 даёт CRUD по каталогу товаров и read-only
  просмотр истории выдачи ключей поверх тех же двух SQLite-таблиц.
- Обе документации проекта (`project_docs/PROJECT_OVERVIEW.md`,
  `API_INTEGRATION.md`) в целом совпадают с фактическим кодом и
  расположением на диске.

## Известные проблемы (подтверждены напрямую чтением кода/конфигурации)

1. **Учётные данные Dr.Web логируются в открытом виде** —
   `app/drweb_client.py` пишет в лог итоговый URL уже с подставленными
   `login`/`pwd` перед выполнением запроса. Не исправлялось (задача была
   ограничена документированием).
2. **Пароль администратора Django захардкожен в `docker-compose.yml`**
   (`office_admin1` / `merchant123`) и присутствует в git-истории
   репозитория в открытом виде (не в `.env`).
3. **Оба сервиса проброшены на `0.0.0.0:8001`/`0.0.0.0:8002` без
   reverse-proxy и TLS** — конфигурации Nginx для них на этом хосте не
   найдено.
4. **Django запущен с `DEBUG = True`, `ALLOWED_HOSTS = ['*']` и
   захардкоженным `SECRET_KEY`** — настройки уровня разработки в
   фактически работающем инстансе.
5. **`test_cffi.py`** на диске сервера (не в git) содержит захардкоженные
   похожие на боевые Dr.Web логин/пароль в открытом виде.
6. **Нет автоматических тестов, CI/CD, линтера** — только ручной скрипт
   `test_cffi.py` для точечной проверки `curl_cffi`.
7. **Неиспользуемые/несоответствующие коду зависимости** в
   `requirements.txt`: `django-environ`, `aiosqlite`, `databases` — не
   найдено их использования в фактическом коде (`os.environ`, синхронный
   SQLAlchemy).

Ни один из этих пунктов не устранялся в рамках этой задачи по прямому
указанию — задача была ограничена документированием текущего состояния.
Полный список неопределённостей — [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).
