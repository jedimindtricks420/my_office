# OVERVIEW — drweb-key-service

Последнее обновление: 2026-09-05 (первичное исследование, TASK-0001).

## Что это

Микросервис для централизованной и безопасной генерации лицензионных ключей
Dr.Web через партнёрский API (`https://f2.drweb.com/remotekeys/`). Выступает
прослойкой между внутренними проектами (Telegram-боты, системы продаж) и
самим Dr.Web: реальные логин/пароль от партнёрского портала хранятся только
в `.env` этого сервиса, а не в каждом проекте-потребителе по отдельности.

Формулировка назначения и раздел "Ключевые преимущества" ниже взяты из
собственного описания проекта (`project_docs/PROJECT_OVERVIEW.md`) —
архитектурные и структурные детали проверены дополнительно напрямую по коду.

## Зачем нужен обходной механизм (curl_cffi)

Dr.Web защищён антифрод-комплексом QRATOR, который блокирует запросы от
типичных серверных HTTP-библиотек. `app/drweb_client.py` использует
`curl_cffi` с `impersonate="chrome"`, эмулирующий TLS-отпечаток (JA3)
браузера Chrome, чтобы запросы доходили до Dr.Web. Подтверждено кодом.

## Из чего состоит (подтверждено кодом)

Два процесса из одного Docker-образа, оркестрованные `docker-compose.yml`:

1. **`drweb-api`** — FastAPI-приложение (`app/`), порт 8001. Единственный
   бизнес-эндпоинт для генерации ключа + вспомогательные (`/health`,
   `/drweb/api/v1/products`, `/drweb/api/v1/logs`).
2. **`drweb-admin`** — Django-админка (`drweb_admin/` + приложение `core/`),
   порт 8002. Веб-интерфейс для управления товарами (`ProductMapping`) и
   просмотра истории выданных ключей (`KeyLog`), доступных только для
   чтения.

Оба процесса читают и пишут в один и тот же файл SQLite
(`data/drweb_keys.db`) — подробности разделения ответственности между
SQLAlchemy и Django ORM см. в [ARCHITECTURE.md](ARCHITECTURE.md).

## Как происходит генерация ключа (подтверждено кодом, `app/main.py` +
`app/drweb_client.py`)

1. Клиент отправляет `POST /drweb/api/v1/generate` с `sku` и `source`,
   передавая статический Bearer-токен в заголовке `Authorization`.
2. FastAPI сверяет токен с `API_KEY` из `.env`.
3. По `sku` ищется запись `ProductMapping` (заранее заведённая через
   Django-админку или изначальную загрузку `app/products.json`).
4. `DrWebClient` подставляет реальные `DRWEB_LOGIN`/`DRWEB_PWD` из `.env` в
   URL-шаблон записи (`full_url`), генерирует случайный `order_item_id`,
   выставляет `comment=api_request`, при необходимости добавляет
   `testing=yes` (управляется `DRWEB_TESTING`).
5. Запрос выполняется через `curl_cffi` (`impersonate="chrome"`), ответ —
   XML, парсится `xmltodict`.
6. Результат (успех с серийным ключом или ошибка) сохраняется в таблицу
   `key_logs` и возвращается клиенту как JSON.
