## Что это

Продукт для партнёров (дилеров) KeysPro.uz: Telegram-бот, через который
партнёр покупает лицензионные ключи (Microsoft Office/Windows, Dr.Web) в
счёт предоплаченного баланса (в сумах), и Django-админка ("KeysPro Admin")
для оператора — управление партнёрами, каталогом товаров, просмотр заказов
и движений баланса.

Название "Partner Bot" встречается в конфигурации Nginx на хосте — это тот
же продукт, что и `tgkeysbot` (см. [DEPLOYMENT.md](DEPLOYMENT.md)).

## Поток покупки (актуальный код, `bot/main.py`)

```
Партнёр в Telegram-боте (aiogram)
  → "Каталог" → выбор товара → выбор количества (1-10)
  → создание Order (status=SENT) сразу, ДО получения ключа
  → получение ключа:
       Product.delivery_source == "drweb" → HTTP POST к внешнему Dr.Web API
       иначе                              → Pyrogram-аккаунт шлёт команду
                                             боту @MicrosoftLeo_Bot, ждёт 60с,
                                             парсит ключ регэкспом из истории чата
  → при успехе: Order.status=DELIVERED, extracted_key сохранён,
                Partner.balance уменьшается на total_price (после факта
                выдачи, без предварительной проверки лимита),
                BalanceLedger(DEBIT) создаётся
  → при неудаче: Order.status=FAILED_PARSE/FAILED_SOURCE, баланс не меняется
```

Отдельный сценарий "Активация" — партнёр присылает Installation ID (≥20
цифр), бот пересылает его тому же боту-источнику и парсит "Confirmation
ID" из ответа; в текущем коде активация бесплатна (`activation_price = 0`
захардкожен в `bot/main.py`).

Полная схема — [ARCHITECTURE.md](ARCHITECTURE.md); поведение баланса и
известные несоответствия — [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).

## Ключевые компоненты (файлы)

- `bot/main.py` — единственный реально работающий процесс бизнес-логики:
  aiogram-бот (клиентский интерфейс партнёра) + постоянно живущий
  Pyrogram-клиент (эмуляция пользователя для общения с ботом-источником),
  в одном asyncio-процессе.
- `bot/drweb_client.py` — HTTP-клиент к внешнему сервису `drweb-key-service`.
- `bot/generate_session.py`, `generate_session.py` (в корне, почти
  идентичный дубликат) — интерактивные скрипты для генерации
  `SESSION_STRING` Pyrogram-аккаунта.
- `core/models.py`, `core/admin.py` — Django ORM и админка (каталог,
  партнёры, заказы, история баланса, инструкции по товарам).
- `config/` — Django settings/urls/wsgi/asgi. Единственный маршрут в
  `config/urls.py` — `/admin/`.
- `transport/tasks.py` — Celery-реализация того же сценария покупки/
  активации с распределённой блокировкой через Redis; **не подключена и
  не может быть запущена** без дополнительных зависимостей и
  инфраструктуры, отсутствующих в проекте (см. [AGENTS.md](../AGENTS.md)).
- `transport/test_pyrogram.py` — ручной скрипт проверки подключения
  Pyrogram-аккаунта (не автоматический тест).

## Кто пользователи

- **Партнёр (дилер)** — модель `Partner`, идентифицируется по
  `telegram_user_id`. Взаимодействует только через Telegram-бота
  (`CLIENT_BOT_TOKEN`). Доступ есть только у партнёров со статусом
  `ACTIVE`; при отсутствии записи или блокировке бот отвечает "Доступ
  отсутствует".
- **Оператор/администратор** — использует Django-админку ("KeysPro
  Admin") для управления партнёрами (включая ручную корректировку
  баланса), товарами, просмотра заказов и истории баланса. Аутентификация
  — стандартная Django-аутентификация (`django.contrib.auth`), отдельных
  ролей/прав кроме стандартных Django-групп/permissions в коде не заведено.
- **Бот-источник `@MicrosoftLeo_Bot`** — внешний Telegram-бот, не
  принадлежащий этому проекту; `tgkeysbot` управляет им косвенно, отправляя
  команды от лица обычного пользовательского Telegram-аккаунта (Pyrogram).

## Каталог товаров

Товары (`Product`) редактируются только через Django-админку, хранятся в
БД (не в файле, в отличие от похожего по духу проекта
`keyspro_auto_sender`). У каждого товара: публичное и внутреннее название,
цена (сум), код товара для команды источнику, источник выдачи
(`telegram_bot`/`drweb`), опционально SKU для Dr.Web, опциональная
инструкция (текст + изображение) для партнёра. На 2026-09-05 фактическое
содержимое каталога (список и количество товаров в продакшн-БД) не
проверялось — см. [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).
