- Три контейнера (`tgkeysbot_db_1`, `tgkeysbot_web_1`, `tgkeysbot_bot_1`)
  запущены; `db` — `healthy`. Образ собран 2026-03-25 и соответствует
  текущему коду на диске (расхождений по mtime не обнаружено), последний
  перезапуск (не пересборка) — 2026-08-20.
- Поток: партнёр в Telegram-боте выбирает товар → бот создаёт `Order` →
  получает ключ либо через Pyrogram-эмуляцию пользователя, отправляющего
  команду стороннему боту `@MicrosoftLeo_Bot` и парсящего ответ regex'ом
  (60 сек ожидания), либо через HTTP-запрос к внешнему сервису
  `drweb-key-service` — в зависимости от `Product.delivery_source`. Баланс
  партнёра списывается после успешной выдачи ключа. Подробности —
  [ARCHITECTURE.md](ARCHITECTURE.md).
- Django-админка ("KeysPro Admin"): управление партнёрами (включая ручную

  чтение) заказов и истории баланса. Доступна публично по адресу
  `https://webhook.keyspro.uz/partner_bot/` — через Nginx-виртуалхост,
  который **делится с не связанным проектом**
  [`keyspro_auto_sender`](../keyspro_auto_sender/AGENTS.md). Подробности —
  [API.md](API.md) и [DEPLOYMENT.md](DEPLOYMENT.md).
- Стек: Django 6.0.3 + PostgreSQL 16 (прод) / gunicorn + whitenoise,
  aiogram 3.26 + Pyrogram 2.0.106, без тестов и CI. Подробности —
  [STACK.md](STACK.md).

## Известные проблемы / расхождения (подтверждены напрямую)

1. **`.dockerignore` не исключает `session_generator.session`
   (живая Pyrogram-сессия), `keyspro.db`, `media.tar.gz`** — все три файла
   подтверждённо присутствуют внутри работающих Docker-контейнеров.
2. **`.env.example` содержит значения, похожие на реальные креды** (не
   плейсхолдеры) для `CLIENT_BOT_TOKEN`/`ADMIN_TELEGRAM_ID`/`API_ID`/
   `API_HASH` — не скопированы в документацию, требуют ручной проверки и,
   при подтверждении, ротации владельцем.
3. **Контейнеры работают от `root`**, порт Django-админки (8080)
   опубликован на `0.0.0.0` хоста, firewall хоста (`ufw`) неактивен —
   единственная защита прямого доступа к 8080 в обход Nginx/TLS не
   подтверждена.
4. **`FORCE_SCRIPT_NAME` не задан в проде**, хотя код и Nginx-конфиг
   предполагают деплой Django-админки под префиксом `/partner_bot` —
   возможное расхождение в генерации ссылок, не проверено живым запросом.
5. **`transport/tasks.py` (Celery + Redis-lock) — нерабочий, неподключённый
   код**: отсутствуют зависимости `celery`/`redis` в `requirements.txt`,
   нет Celery-приложения, нет сервисов worker/Redis в `docker-compose.yml`.
   Дублирует логику `bot/main.py`, но решает проблему конкурентности
   единственного Pyrogram-аккаунта, которая в актуальном коде не решена.
6. **Нет проверки лимита долга (`negative_limit`) перед покупкой** —
   партнёр может продолжать покупать в долг без ограничения, получает лишь
   разовое уведомление при первом пересечении лимита.
7. **`SourceAccount` и `Settings` (модели в БД) не используются
   актуальным кодом `bot/main.py`** — конфигурация Pyrogram берётся из
   `.env`, цена активации захардкожена как 0 (бесплатно).
8. **`keyspro.db` (не-Django схема) и `db.sqlite3` (Django-схема, но не
   прод-БД) — не используемые актуальным кодом файлы** в корне проекта.
9. **Нет README, git-репозитория, автоматических тестов и CI.**

Полный список с деталями — [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).
