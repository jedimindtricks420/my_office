## Процесс/деплой

- Один процесс `uvicorn app.main:app` внутри одного Docker-контейнера
  (`key-distributor`, см. `docker-compose.yml`). Нет отдельных
  worker/queue-процессов — фоновая обработка заказа выполняется через
  `fastapi.BackgroundTasks` в том же процессе, что принял HTTP-запрос.
- Nginx на хосте терминирует TLS (Let's Encrypt/Certbot) и проксирует весь
  трафик `webhook.keyspro.uz` на `127.0.0.1:8000`. Тот же server-блок Nginx
  проксирует `/partner_bot/` на отдельный, не относящийся к этому
  репозиторию backend на `127.0.0.1:8080` — совместное использование
  домена, не связанное architecturally с `keyspro_auto_sender`.
- Порт 8000 контейнера опубликован на хосте (`0.0.0.0:8000` — подтверждено
  `docker ps`), доступ извне ограничивается только тем, что Nginx —
  единственный настроенный публичный вход; порт 8000 как таковой не
  блокируется на уровне приложения или явно проверенного firewall.

## Два независимых пути получения ключа

Выбор пути определяется полем `"source"` компонента в `product_config.json`
(по умолчанию, если поле отсутствует, — `"telegram"`):

1. **Telegram/Pyrogram (`KeyProvider`)** — процесс аутентифицируется в
   Telegram как обычный пользователь (`SESSION_STRING` или файл сессии),
   отправляет текстовую команду (например `/401`) целевому боту
   `@MicrosoftLeo_Bot`, ждёт 60 секунд, затем ищет в последних 2
   сообщениях чата строку "Purchase Successful" и извлекает ключ регулярным
   выражением `\b([A-Z0-9]{5}-){4}[A-Z0-9]{5}\b`. До 2 попыток с паузой 5
   секунд.
2. **Dr.Web API (`DrWebProvider`)** — HTTP POST на `DRWEB_API_URL` с
   `Authorization: Bearer DRWEB_API_KEY`, телом `{"sku": <command>,
   "source": "keyspro_auto_sender"}`, ожидает JSON-ответ с полем `serial`.
   Таймаут 20 секунд, без повторных попыток на этом уровне (в отличие от
   Telegram-пути).

## Персистентность

- **SQLite** (`keyspro.db`) — единственное хранилище состояния (заказы,
  выданные ключи). Создаётся и живёт внутри файловой системы контейнера;
  `docker-compose.yml` монтирует только `.env`, `app/` и
  `product_config.json` как bind mounts — файла БД среди них нет
  (подтверждено `docker inspect`/`docker exec`). См. риск в
  [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).
- **`product_config.json`** — каталог товаров, читается заново при каждой
  обработке заказа (`load_product_config()` в `processor.py`) и
  редактируется напрямую через дашборд (перезаписывает файл целиком).

## Границы системы

- Внешние зависимости: WooCommerce (источник webhook), Telegram (Pyrogram
  юзер-сессия + `python-telegram-bot` для уведомлений), SMTP-сервер
  (`mail.keyspro.uz`), внешний HTTP API `drweb-key-service` (не в этом
  репозитории — см. [AGENTS.md](../AGENTS.md)).
- Внутри репозитория нет очередей, кэшей или отдельных микросервисов —
  всё внутри одного FastAPI-приложения.
