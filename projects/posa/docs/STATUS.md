## 2026-10-24 — канал продаж через терминалы Paynet

Развёрнут в production. Подробности — [PAYNET.md](PAYNET.md).

- Приёмник UWS (JSON-RPC 2.0) отдельным процессом: контейнер
  `activation-uws`, `127.0.0.1:4010`. Публичный адрес
  **`https://paynet.namo.uz/api/payments/uws/paynet`**, сертификат
  Let's Encrypt до 2027-01-22; на поддомене доступны только роуты UWS и
  `/healthz`, остальное отдаёт 404.
- Официальный тестер Paynet: **13 проверок из 13** в режиме «многоразовые
  платежи, без отмены» — единственном, который соответствует модели
  продажи товаров.
- Три новые таблицы (`PartnerService`, `PartnerServiceItem`,
  `PartnerTransaction`), `Product.kassaId`, `Kassa.totalReceivedPaynet`,
  уникальный индекс на `QrPaymentAttempt.externalPaymentId`.
  Миграция `20261024151500_paynet_partner_channel`.
- Раздел админки «Партнёрские сети» с журналом транзакций.
- Цена продажи теперь берётся из фактически списанной суммы, а не из цены
  товара — чек и выплаты сходятся с деньгами.

Исправлено попутно (все ошибки существовали до этой работы):

1. Гонка за последним ваучером в онлайн-потоке — один код мог уйти двум
   клиентам; защита из `saleController` перенесена в `processPaymentInternal`.
2. Падение генерации чека после коммита возвращало ошибку платежа, хотя
   ваучер уже израсходован.
3. `/admin/rokky/activations` и `/admin/drweb/activations` падали с 500:
   сортировка по несуществующему полю `createdAt` вместо `activatedAt`.
4. Фильтр по телефону в активациях Rokky искал `client.phone` вместо
   `client.phoneNumber`.
5. Страницы выплат и транзакций мерчанта/вендора падали с 500 на
   несуществующем `id`.
6. `POST /auth/login` без тела или с чужим `Content-Type` давал 500.
7. Ограничители доступа отдавали голый 403 не вошедшему пользователю
   вместо формы входа.
8. Создание товара теряло причину сбоя в `catch` без логирования.
9. Таблицы админки не помещались на экран: контейнер 1280px при 7–10
   колонках.
10. Касса начислялась по партнёрскому каналу из-за двух неявных откатов на
    кассу вендора — в `resolveKassaId` и в `processPaymentInternal`. Продажа
    через терминал увеличивала `totalReceivedPaynet` и баланс кассы, то есть
    система записывала «получено кассой» то, что придёт банковским переводом
    позже. Теперь касса берётся только там, где указана явно; поведение
    Click/Payme/Alif и QR-потока не изменилось (проверено отдельно).

**2026-10-26.** Проверка номера телефона в партнёрском канале упрощена до
проверки формата: белый список кодов операторов убран. Причина — пропуск в
списке отсекал бы реальных покупателей, а ошибочный номер и так не проходит:
SMS не доставляется, а вход в кошелёк идёт по коду из SMS. Подробности —
[PAYNET.md](PAYNET.md).

**Не закрыто:**

- откат выдачи при `CancelTransaction` — политика с Paynet не согласована;
- allowlist IP партнёра в nginx: блок подготовлен, но закомментирован.
  Включить до создания первой услуги;
- настоящие `serviceId` от Paynet; услуг в production пока 0;
- позиции услуг и привязки `MerchantProductLink` к мерчанту канала
  (`office_admin_paynet`, id 21) — мерчант заведён, привязок пока 0;
- удаление пользователя по GET-ссылке (`GET /admin/users/:id/delete`) —
  требует перевода на POST с CSRF-токеном.

Поддомен и TLS для шлюза — сделаны.

## Что подтверждено и работает

- **Backend** (`activation-system`, Node.js 20 + Express 5 + Prisma 6 +
  PostgreSQL 16) работает в Docker, контейнер `activation-system` up 2
  недели на момент проверки, слушает порт 4000 (плюс отдельный проброс 4001
  для `api.namo.uz`).
- **Nginx** маршрутизирует 8 поддоменов `*.namo.uz` на этот же backend по
  имени хоста; приложение само разруливает роль по `Host` в
  `middleware/checkSubdomain.js`. Подробности — [DEPLOYMENT.md](DEPLOYMENT.md).
- **Схема данных**: 36 моделей, 12 enum'ов, 28 миграций Prisma (с
  2025-02-11 по 2026-07-30) — задокументированы в [DATABASE.md](DATABASE.md).
- 185 объявлений HTTP-маршрутов (`router.get/post/put/delete`) по 14 файлам
  роутеров (из них 4 — в неиспользуемом `routes/apiV1.js`, см.
  OPEN_QUESTIONS.md) задокументированы в
  [API.md](API.md); аутентификация — сессии (`express-session` +
  `connect-pg-simple`, хранение в той же Postgres) с ролевыми middleware для
  сотрудников и отдельная OTP-по-телефону авторизация для клиентов.
- Три платёжных провайдера как webhook-интеграции (Click, Payme, Alifpay) +
  собственный QR-платёж, реквизиты — per-кассе в таблице `Kassa`, а не
  только в `.env`.
- PWA-кошелёк клиента + Android TWA-обёртка (`my-pwa/`, Bubblewrap) с
  публикацией на `wallet.namo.uz`.
